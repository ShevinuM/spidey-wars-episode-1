# Claude Design mirror

The two DesignSync rituals — pulling mockups and sprites in, pushing rendered scenes out — and the pinned project identities that keep them from crossing wires. Both run only from the main session.

## What it is

- [ ] **R001** `.design-sync/config.json` pins two independent DesignSync relationships: a `source` project (read-only mockups and sprites) and a `mirror` project (write-only rendered scene snapshots). Never conflate them — the pull ritual only reads `source`, the push ritual only writes `mirror`.
- [ ] **R002** Both rituals run exclusively from the main session. DesignSync tools are not available to subagents or executors, so a plan step needing `get_file`, `list_files`, `finalize_plan`, or `write_files` is never delegated to one.

## Precondition

- [ ] **R003** Every DesignSync call — `get_file`, `list_files`, `finalize_plan`, `write_files`, all of them, including the read-only ones — fails with "DesignSync needs design-system authorization" until `/design-login` has been run in that session. It is interactive-only; nothing automated can grant it. Confirm it has been run before the first DesignSync call of either ritual, not after the first failure. This is a DesignSync-tool constant, not a project-specific setting.

## Source pull

- [ ] **R004** The `source` project (`.design-sync/config.json` → `source.projectId`) is read-only: fetch a mockup or sprite with DesignSync `get_file` only — never write back to it.
- [ ] **R005** A pulled mockup lands in `reference/design/` and a pulled sprite in `assets/sprites/` as a local copy; build and test code reads only those local copies, never DesignSync itself at runtime or in CI. A pulled `.dc.html` file is visual reference only, never rendered or executed by the game.
- [ ] **R006** A sprite pulled from the source project has its C2PA content-credentials metadata stripped before it is committed — never commit a sprite still carrying embedded C2PA provenance data.
- [ ] **R007** Not every asset in the source project is pulled — a scratch or alternate asset the game never loads (a zoom crop, an alternate pose kept for reference) stays in the Design project. Pull only what the shipped game actually loads or what a mockup file references as its layout source of truth.

## Mirror push

- [ ] **R008** The mirror is not a component design system — it is one `.dc.html` snapshot per rendered Phaser scene state, generated by `scripts/generate-design-mirror.ts` into `ds-bundle/pages/**` (gitignored, never committed to the repo itself).
- [ ] **R009** Every generated mirror page has zero `<script` occurrences — the mirror is a static snapshot, never a live page. Verified with `grep -c "<script" ds-bundle/pages/*.dc.html` reporting `0` for every file.
- [ ] **R010** Every generated mirror page makes zero outbound network requests — no `http://`/`https://` reference remains anywhere in the serialized output. Verified with `grep -c "https\?://" ds-bundle/pages/*.dc.html` reporting `0` for every file.
- [ ] **R011** Regenerating and pushing the mirror is not optional after a change that alters what a scene renders — it happens as part of that same work session, never deferred as a separate follow-up.
- [ ] **R012** Push in three steps, in order: (1) `list_files` against the pinned mirror project, so a scene renamed or deleted since the last push gets an explicit entry in the next step's `deletes` rather than leaving a phantom page in the mirror; (2) `finalize_plan` (`localDir: "ds-bundle"`, `writes: ["pages/**"]`, `deletes` passed explicitly — even `[]`, since omitting it is a hard error); (3) `write_files`.
- [ ] **R013** Never create a second mirror project once `.design-sync/config.json`'s `mirror.projectId` is populated — one pinned project, always pushed to, never a fresh one to avoid a merge.
- [ ] **R014** CI never pushes to the mirror. The push is a documented developer ritual performed by hand from the main session, same as the pull — nothing automated runs it.
