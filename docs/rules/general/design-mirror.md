# Claude Design mirror

The two DesignSync rituals — pulling mockups and sprites in, pushing rendered scenes out — and the pinned project identities that keep them from crossing wires. Both run only from the main session.

## What it is

- [ ] **R001** `.design-sync/config.json` pins two independent DesignSync relationships: a `source` project (read-only mockups and sprites) and a `mirror` project (write-only rendered scene snapshots). Never conflate them — the pull ritual only reads `source`, the push ritual only writes `mirror`.
- [ ] **R002** Both rituals run exclusively from the main session. DesignSync tools are not available to subagents or executors, so a plan step needing `get_file`, `finalize_plan`, or `write_files` is never delegated to one.

## Source pull

- [ ] **R003** The `source` project (`.design-sync/config.json` → `source.projectId`) is read-only: fetch a mockup or sprite with DesignSync `get_file` only — never write back to it.
- [ ] **R004** A pulled mockup lands in `reference/design/` and a pulled sprite in `assets/sprites/` as a local copy; build and test code reads only those local copies, never DesignSync itself at runtime or in CI. A pulled `.dc.html` file is visual reference only, never rendered or executed by the game.
- [ ] **R005** A sprite pulled from the source project has its C2PA content-credentials metadata stripped before it is committed — never commit a sprite still carrying embedded C2PA provenance data.
- [ ] **R006** Not every asset in the source project is pulled — a scratch or alternate asset the game never loads (a zoom crop, an alternate pose kept for reference) stays in the Design project. Pull only what the shipped game actually loads or what a mockup file references as its layout source of truth.

## Mirror push

- [ ] **R007** The mirror is not a component design system — it is one `.dc.html` snapshot per rendered Phaser scene state, generated by `scripts/generate-design-mirror.ts` into `ds-bundle/pages/**` (gitignored, never committed to the repo itself).
- [ ] **R008** Regenerating and pushing the mirror is not optional after a change that alters what a scene renders — it happens as part of that same work session, never deferred as a separate follow-up.
- [ ] **R009** Push with the DesignSync tool in two calls, in order: `finalize_plan` (`localDir: "ds-bundle"`, `writes: ["pages/**"]`, `deletes` passed explicitly — even `[]`, since omitting it is a hard error), then `write_files`.
- [ ] **R010** Never create a second mirror project once `.design-sync/config.json`'s `mirror.projectId` is populated — one pinned project, always pushed to, never a fresh one to avoid a merge.
- [ ] **R011** CI never pushes to the mirror. The push is a documented developer ritual performed by hand from the main session, same as the pull — nothing automated runs it.
